# Using `--warp-spec` with `specify init`\n\n## Overview\n\nThe `--warp-spec` flag enables autonomous Spec-Driven Development (SDD) initialization when running `specify init`. It bootstraps a complete SDD architecture including:\n\n- **WARP.md** – Project-specific development guidance (stack-aware)\n- **memory/constitution.md** – Project principles and quality standards\n- **specs/** directory – Structured SDD artifact templates\n- **Agent-specific commands** – Ready-to-use `/speckit.*` commands\n\n## Key Requirement: AI Assistant Selection\n\n**Important:** When using `--warp-spec`, you must also select an AI assistant because:\n\n1. **Template Download** – The Specify CLI needs to download a template for your chosen AI (Claude Code, GitHub Copilot, Cursor, etc.)\n2. **Template Extraction** – The template files are extracted to your project\n3. **SDD Bootstrap** – THEN the `--warp-spec` hook runs to set up SDD artifacts on top\n\nThe workflow is:\n```\nAI Selection → Template Download/Extract → Project Detection → SDD Initialization\n```\n\n## Usage Examples\n\n### Explicit AI Selection (Recommended)\n\n```bash\n# Initialize existing project with SDD (Claude Code)\nspecify init --here --ai claude --warp-spec\n\n# Initialize existing project with SDD (GitHub Copilot)\nspecify init --here --ai copilot --warp-spec\n\n# Create new project with SDD\nspecify init my-project --ai claude --warp-spec\n```\n\n### Interactive AI Selection\n\n```bash\n# Initialize with interactive agent menu\nspecify init --here --warp-spec\n# Then use arrow keys to select an AI assistant\n\n# Or for a new project\nspecify init my-project --warp-spec\n# Then select an AI assistant when prompted\n```\n\n## What Happens During Initialization\n\nWhen you run `specify init --here --ai claude --warp-spec`:\n\n1. ✅ **Precheck** – Verify git, Claude Code, and other tools\n2. ✅ **AI Selection** – `claude` (already selected via `--ai`)\n3. ✅ **Script Selection** – Choose between `sh` (Unix) or `ps` (PowerShell)\n4. ✅ **Download Template** – Fetch the Specify template from GitHub\n5. ✅ **Extract Template** – Merge template files into your project\n6. ✅ **Setup SDD** – Auto-detect tech stack and initialize SDD artifacts\n   - Detect: Node.js, Python, Go, Java, .NET, Rust, or generic\n   - Generate: Stack-aware WARP.md with build/test commands\n   - Create: constitution.md, specs/, agent configs, helper scripts\n7. ✅ **Initialize Git** – Create initial commit (if git available)\n8. ✅ **Next Steps** – Display available `/speckit.*` commands\n\n## Available AI Assistants\n\nChoose from:\n\n- `claude` – Claude Code (requires installation)\n- `copilot` – GitHub Copilot (IDE-based)\n- `cursor-agent` – Cursor (IDE-based)\n- `gemini` – Gemini CLI (requires installation)\n- `windsurf` – Windsurf (IDE-based)\n- `qwen` – Qwen Code (requires installation)\n- `opencode` – opencode (requires installation)\n- `codex` – Codex CLI (requires installation)\n- `kilocode` – Kilo Code (IDE-based)\n- `auggie` – Auggie CLI (requires installation)\n- `codebuddy` – CodeBuddy (requires installation)\n- `roo` – Roo Code (IDE-based)\n- `q` – Amazon Q Developer CLI (requires installation)\n- `amp` – Amp (requires installation)\n- `shai` – SHAI (requires installation)\n\n## Troubleshooting\n\n### \"Warp is not available\" or similar errors\n\nIf you see an error during SDD initialization:\n\n```bash\n# Re-run with verbose debugging\nspecify init --here --ai copilot --warp-spec --debug\n```\n\nThis will show detailed error messages for:\n- Project detection issues\n- WARP generation failures\n- SDD bootstrap problems\n\n### Agent selection menu appears but no SDD setup\n\nThis is **normal**. The workflow is:\n\n1. Select agent from menu (or use `--ai` to skip)\n2. Select script type (or press Enter for default)\n3. Download and extract template\n4. **Then** SDD setup runs automatically (if `--warp-spec` was passed)\n\nWatch the step tracker output for the \"Setup Spec-Driven Development\" phase.\n\n### Git not found\n\n```bash\n# Skip git initialization\nspecify init --here --ai copilot --warp-spec --no-git\n\n# Or initialize manually later\ncd your-project\ngit init\ngit add .\ngit commit -m \"Initial commit\"\n```\n\n### Agent tool not found\n\n```bash\n# Skip agent tool checks (useful for IDE-based agents)\nspecify init --here --ai claude --warp-spec --ignore-agent-tools\n```\n\n## After Initialization\n\nOnce `--warp-spec` setup completes, you have a full SDD project ready:\n\n```bash\ncd your-project\n\n# Next steps: Use slash commands with your AI agent\n/speckit.constitution   # Review/refine project principles\n/speckit.specify        # Write first feature specification\n/speckit.plan          # Create technical implementation plan\n/speckit.tasks         # Generate implementation tasks\n/speckit.implement     # Execute tasks\n```\n\n## Idempotency\n\nYou can safely run `--warp-spec` multiple times:\n\n```bash\n# First run: Creates constitution, specs/, WARP.md, etc.\nspecify init --here --ai copilot --warp-spec\n\n# Later: Adds new artifacts, preserves existing edits\nspecify init --here --ai copilot --warp-spec --force\n```\n\n**What's preserved:**\n- User edits to `memory/constitution.md`\n- Existing feature specs in `specs/`\n- User-added WARP.md sections\n\n**What's updated:**\n- Auto-managed WARP.md sections (marked with `<!-- specify-init:warp-managed -->`)\n- Stack detection (refreshed each run)\n- Agent command definitions\n\n## Generated Artifacts\n\nAfter `--warp-spec` runs, your project will have:\n\n```\nyour-project/\n├── memory/\n│   └── constitution.md          # Project principles (stack-aware)\n├── WARP.md                      # Root-level guidance\n├── specs/\n│   ├── README.md               # SDD explanation\n│   ├── _templates/             # Templates for specs/plans/tasks\n│   └── example-feature/        # Sample feature spec (optional)\n├── .specify/\n│   ├── agents/                 # Agent-specific commands\n│   ├── scripts/                # Helper scripts (bash/PowerShell)\n│   └── templates/              # SDD artifact templates\n└── (src/, tests/, etc.)        # Generated WARP.md for subdirs\n```\n\n## FAQ\n\n**Q: Can I use `--warp-spec` without specifying an AI?**  \nA: Yes, you'll see an interactive menu to select an agent, then SDD setup proceeds.\n\n**Q: Does `--warp-spec` modify existing code?**  \nA: No. It only creates SDD artifacts and auto-managed WARP.md sections. User code is never touched.\n\n**Q: Can I use `--warp-spec` on a project that already has SDD?**  \nA: Yes. It will update WARP.md markers, refresh stack detection, and preserve existing specs.\n\n**Q: What if my project uses an unsupported tech stack?**  \nA: The detector falls back to \"generic\" mode and creates a generic WARP.md. You can customize it manually.\n\n**Q: Can I disable `--warp-spec` for certain projects?**  \nA: Yes, just don't pass the flag. Use `specify init --here --ai copilot` without `--warp-spec` to skip SDD setup.\n"
